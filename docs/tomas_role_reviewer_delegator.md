# SANASTA Tomo vaidmuo: tikrintojas, deleguotojas, sprendimu priemejas

## Paskirtis

Sis dokumentas apibrėžia naują SANASTA valdymo principą: Tomas neturi būti pagrindinis rankinio darbo vykdytojas sistemoje. Tomas turi būti tikrintojas, deleguotojas ir sprendimų priėmėjas.

Tikslas: kuo mažiau Tomo laiko prie kompiuterio, kuo daugiau aiškių sprendimų, delegavimo ir verslo valdymo.

## Pagrindinė taisyklė

Tomas neturi ieškoti, kopijuoti, suvedinėti, gaudyti ir priminti pats.

Sistema turi:

- surinkti informaciją;
- ištraukti esmę;
- priskirti stalčių;
- nustatyti prioritetą;
- paruošti veiksmą;
- deleguoti robotui arba žmogui;
- parodyti Tomui tik tai, ką reikia patikrinti arba nuspręsti.

## Tomo vaidmuo

Tomas turi būti:

- tikrintojas;
- deleguotojas;
- sprendimų priėmėjas;
- kainos ir nuolaidos tvirtintojas;
- konfliktų ir atsakomybės ribų sprendėjas;
- verslo krypties nustatytojas;
- galutinis DECISION žmogus.

## Ko Tomas neturi daryti

Tomas neturi rankomis:

- ieškoti tarp 13 įvykių;
- kopijuoti informacijos tarp Gmail, WhatsApp, Trello, Calendar ir CRM;
- prisiminti, kam išsiųsta sąskaita;
- tikrinti, ar išsiųsta poįrengiminė instrukcija;
- sekti kiekvieno follow-up;
- ieškoti kliento istorijos pokalbiuose;
- rankomis ruošti pasikartojančių laiškų;
- rankomis kurti kiekvieno tasko, jei sistema gali jį paruošti;
- būti žmogaus API tarp sistemų.

## Ką turi daryti sistema

Sistema turi paruošti Tomui:

- vieno lango vaizdą;
- 3 šiandienos A prioritetus;
- DECISION sąrašą;
- deleguotus robotui darbus;
- laukiančius pinigus;
- objektus, kuriuos galima uždaryti;
- laiškų ir WhatsApp atsakymų juodraščius;
- kalendoriaus įrašų juodraščius;
- CRM / Trello įrašus;
- skolų ir follow-up priminimus.

## Sprendimų riba

Sistema gali ruošti ir deleguoti, bet negali pati priimti sprendimų dėl:

- kainos;
- nuolaidos;
- konflikto;
- garantijos;
- atsakomybės prisiėmimo;
- skolos ginčo;
- institucijų atsakymų;
- didesnio objekto;
- partnerystės;
- nestandartinio termino;
- situacijos, kuri gali tapti SANASTA pozicija ginče.

Tokie atvejai visada yra DECISION.

## Darbo formulė

```text
Informacija -> eventas -> prioritetas -> juodraštis / užduotis -> Tomas patikrina -> sistema vykdo
```

## Trumpa valdymo formulė

```text
Sistema surenka.
Sistema filtruoja.
Sistema paruošia.
Tomas tikrina.
Tomas deleguoja.
Tomas sprendžia.
```

## Kodėl tai svarbu

SANASTA negali augti, jei Tomas lieka pagrindinis informacijos pernešėjas tarp sistemų.

Augimas įmanomas tik tada, kai sistema pati paruošia darbą, o Tomas lieka prie sprendimų, vertės ir kontrolės.
